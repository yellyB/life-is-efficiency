### 1. 문서를 토대로 개발할때 겪은 문제 - 문서대로 개발해도 코드에 과거 기능의 흔적이 남는다

문서를 토대로 개발시키기 위해 문서를 구체적으로 작성했다. 예를들어 기획, 게임 디자인, 아이템, 스킬, 몬스터, 무기, 개발 계획 등 여러 문서를 만들고 체계적으로 관리했다. 그런데 기능을 바꾸거나 없앨 때 코드가 깔끔하게 정리되지 않는 경우가 있었다.

예를 들어 어떤 기능의 코드가 여러 곳에 나뉘어 있고, 다른 부분과 연결되는 지점은 한 곳뿐이라고 하자. 기능을 없앨 때 연결 지점만 삭제하고 세부 구현은 남겨두는 경우가 종종 있었고, 그때문에 실제로는 사용하지 않는 코드나 에셋이 남아있었다.

웹 개발로 비유하면 페이지에서 컴포넌트를 사용하는 부분만 지우고 해당 컴포넌트 자체, 그 변경으로 인한 CSS 값 조정, 해당 컴포넌트에서만 쓰던 유틸 함수 등은 그대로 두는 것들이다.

흔적이 남는 것 자체도 문제지만, 더 큰 문제는 나중에 코드를 분석할 때 잘못된 분석을 하게만든다는 점이다. 이미 삭제한 기능을 아직도 구현되어 있다고 착각하는 식이다. 그래서 프로토타입 게임을 토대로 정식 버전 게임을 만들 때, 초반에 잠깐 넣었다가 뺀 기능을 정식 버전 작업 중에도 살아 있는 기능이라고 오해하는 경우가 있어서, 그 부분을 완전히 끊어내는데 고생을 했다.

### 2. 코드를 토대로 문서를 수정할때 겪은 문제 - 코드를 기준으로 문서를 고칠 때는 관련 내용을 빠짐없이 찾기 어렵다

문서가 코드와 직접 연결되어 있는게 아니기 때문에, 코드가 바뀌었을때 문서의 어떤 항목을 수정해야 하는지 정확히 알지 못했다. 새로운 내용을 추가하는 일은 비교적 수월했지만, 기존 내용을 삭제하거나 수정할 때는 문제가 생겼다.

같은 기능이 여러 문서에 조금씩 나뉘어 적혀 있는 경우도 있고, 문서마다 사용하는 용어나 세부 내용이 조금씩 달라서 그런지 한 곳만 수정해버리고 끝나서 다른 문서에는 오래된 내용이 여전히 남았다. 코드에서 기능을 삭제했더라도, 관련 문서의 정확한 위치를 찾아 지적하지 않으면 문서 전체에서 깔끔하게 제거되지 않은 적이 있다.

그래서 AI에게 문서 수정을 맡기더라도, 최소한 어떤 내용이 어느 문서에 적혀 있는지 파악하는것이 필요하다고 느꼈다.

### 3. 코드상으론 맞을지몰라도 개발자의 의도에 맞아야 한다

모든 요구사항을 문서에 적어두고 작업을 시키더라도, AI가 코드만 보고는 정말 풀어야 할 문제를 알아내지 못하는 경우가 있다.

kill-grass게임을 예로 들자면, 모바일 게임에서 풀을 그리는 기능이 필요했다. 문서에는 모바일에서 실행한다고 분명히 적었지만, PC에서 개발해서인지 AI는 모바일에서 생길 수 있는 성능 문제를 고려하지 않았다. 코드는 틀리지 않았지만 의도와는 맞지 않는 방향으로 개발된 것이다.

그래서 “모바일이 대상이므로 CPU 부담을 줄이고 GPU를 활용하는 방향으로 그려야 한다”처럼 문제의 맥락과 해결 방향을 제시했더니, 그 방향대로 빠르게 작업을 완료해주었다. AI가 코드를 작성할 수는 있어도, 개발자의 방향 제시가 필요하다는 내용의 전형적인 예시를 직접 경험하게 되었다.

### 4. AI와 내가 원하는 구현 방향이 다르다

kill-grass게임에서 계속 직접 테스트를 해야하는 번거로움때문에, 그 이후 만든 slot-kitchen게임에서는 시뮬레이션 코드로 헤드리스 검증을 할 수 있도록 설계했다.

그런데 시뮬레이션에는 문제가 있었다. 시뮬레이션을 돌려서 내가 요구한 밸런스를 맞춰달라고 요구했고 결과를 확인했을때는 잘 되는듯 보였다. 하지만 나중에 알고보니 사실 AI는 내가 요구한 사항만 딱 통과하도록 시뮬을 돌렸던것이다. 무슨 말이냐면, 나는 버프 카드의 밸런스를 맞추기 위해 모든 버프카드에 대한 시뮬을 돌려서 효율을 일정하게 맞추고 싶었으나, AI는 내가 시키지도 않았는데 알아서 시뮬로 검증이 어려운 버프카드는 검증 대상에서 제외시키고 밸런스를 맞춘것이었다.

테스트를 시킬때도 결과만 보고 무조건 믿으면 안되고, 정확한 프롬프트 지시의 중요성도 느낄 수 있었다.

이 유튜브 영상을 보니 위 내용이 생각났다. 중~후반부에 나오는 내용인데, 요약하자면 AI가 지시자의 요구를 맞추기 위해 효율적인 방법을 찾았고, 그게 인간으로 치면 요령을 부려서 결과만 요구사항에 맞춰 진화(?)했다는 내용이다.
